# Publish an existing video

Work from kit root. Read `tools/publisher/README.md` for exact commands. Use `node tools/publisher/dist/cli.js`, built by `setup/setup.ps1`. Verify the chosen Node executable is version 22+ and that the build exists; if PATH selects an older version, check for an installed compatible runtime before proposing an upgrade. No Studio backend or browser automation is needed.

1. Read `local/accounts.json`; run `accounts` to list connected IDs and `check` to validate selected accounts when setting up or recovering a connection. Do not guess destinations. One or multiple API keys are supported, with each selected platform owned by exactly one configured API profile. `accounts` queries only profiles declared in that file: storing a secondary key alone does not register a secondary profile. When a user requests multiple credential groups, declare their aliases and `apiKeyEnv` names without secrets, list accounts, then map the returned IDs. Do not overwrite unrelated existing profiles or infer additional posting destinations from a key's available connections.
2. Draft metadata in the project directory using `config/publish.example.json` before running `prepare`. Prefer a specific, engaging title and a concise caption that adds useful context; avoid repeating the full title and lesson outline by default. Use the actual content and user style. A human-recorded video edited by AI does not automatically require an AI-generated-media label. Resolve YouTube kids audience, synthetic media, visibility, TikTok privacy and Facebook feed/reel type together, reusing choices already supplied. Show the exact copy and destinations while they are cheap to revise; `prepare` uploads the video for each selected API profile. Never impose personal branding or all four platforms.
3. Run `import --run <id> --video <mp4>` once to record the existing file, then `prepare --run <id> --metadata <json>`. Preparation uploads media to Zernio storage and validates payloads but creates no post. It produces `review.json` inside the ignored run folder; show the exact video, captions, destinations, visibility and immediate/scheduled mode to the user. Keep presigned/public media URLs private.
4. Run `publish --run <id> --confirm-publish` only when user authorization covers that reviewed plan. If inputs or plan change, prepare and review again within the existing run before publishing starts. Review does not require another approval when the user's existing authorization already covers the revised plan; ask only for a material unresolved choice. CLI flags are assertions of authorization, not substitutes for it.
5. Run `status --run <id>` for a local checkpoint or `inspect --run <id>` for fresh remote status. Report published/scheduled/partial/failed/publishing accurately. A successful profile must never be recreated to repair another profile.

When a CLI command outlives the tool's initial wait, retain its returned session ID and poll that process. A tool yield is not an API timeout. Do not rerun `publish` to recover missing output. `status` can read the checkpoint while a process holds the run lock; wait for that process to finish before commands that also take the lock, including `inspect`. Never remove a live process's lock.

For an uncertain response, inspect first. Report each platform separately: one profile can time out while another has published, and an aggregate `publishing` status can coexist with individual `published` results. A missing permalink does not imply failure. Do not start a new run or repeatedly retry creation. `retry --run <id> --confirm-publish` only retries recorded failed attempts with known post IDs using Zernio's retry endpoint; pending attempts known not to have been sent may resume. Uncertain attempts without an ID require reconciliation using `adopt --run <id> --profile <alias> --post-id <id>` after verifying the matching post in Zernio. Use available documented read-only inspection to find it; if that cannot resolve the attempt, request the post ID from the user. Never treat a timeout or lack of a link as evidence that no post was created.

TikTok direct posting may be unavailable due to account/platform limits. Report it; do not silently switch to Creator Inbox, change privacy, strip a platform or alter content to evade duplicate detection. This version does not automate an Inbox fallback. Stop and offer manual Zernio resolution.

Never print or commit keys. CLI reads only process environment or `local/secrets.env`; commands accept no key arguments. Do not copy the original author's credentials or account configuration.
